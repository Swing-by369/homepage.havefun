# サイト構成・デザイン提案書

> 事業内容：AI導入支援・DXコンサルティング／受託システム開発／IT人材育成
> 本書は実装前の「設計合意」のための提案書です。内容にご合意いただいた後、コーディングへ進みます。

---

## 0. コンセプト

**「入れて終わり」にしない。現場が"自走"できるまで伴走するDXパートナー。**

- ツール導入や開発の請負ではなく、**現場の内製化・自走**をゴールに置くことを一貫したメッセージにします。
- トーンは「先進的・知的・信頼できる」。ダークUIで先端テック感を出しつつ、余白とタイポグラフィで"上品なSaaS"の落ち着きを両立します。

---

## 1. サイト全体構成（ページマップ）

```
トップ（/）
├─ サービス詳細（/services）
│    ├─ AI導入支援・DXコンサル
│    ├─ 受託システム開発
│    └─ IT人材育成・研修
├─ 導入事例・実績（/works）   ← トップ内に要約 + 詳細ページ
├─ 料金・プラン（/pricing）
├─ 会社概要・メンバー（/about）
├─ お知らせ／ブログ（/news）
│    └─ 記事詳細（/news/:slug）
├─ よくある質問（/faq）       ← 独立 or トップ内セクション
└─ お問い合わせ（/contact）
     └─ 無料オンライン相談（30分）予約導線
```

### 必須ページの対応表

| ご要望 | 対応ページ |
| --- | --- |
| トップページ | `/` |
| サービス詳細 | `/services`（3事業を1ページに整理、各事業へアンカー） |
| 会社概要（メンバー紹介） | `/about` |
| お知らせ（ブログ枠） | `/news` + 記事詳細 |
| 問い合わせフォーム | `/contact` |

> 初期リリースは「トップ + サービス + 会社概要 + お知らせ + 問い合わせ」を実装し、料金・FAQ・事例はトップ内セクション＋必要に応じて個別ページ化、という段階構成を推奨します。

## 2. グローバル要素（全ページ共通）

### ヘッダー（固定・スクロールで半透明＋ぼかし）
- 左：ロゴ
- 中央〜右：サービス / 実績 / 料金 / 会社概要 / お知らせ
- 右端CTA：**「無料相談（30分）」** をネオングリーンのボタンで常時表示

### フッター
- 事業概要の一言 / サイトマップ / 会社情報 / SNS / プライバシーポリシー
- 最下部にもう一度「無料相談」CTAを配置（離脱直前の取りこぼし防止）

### 追従CTA（任意）
- スクロール時、右下に控えめな「無料相談」フローティングボタン

## 3. トップページのセクション構成（縦の流れ）

スクロールするだけで「課題提起 → 解決策 → 信頼の証明 → 行動」が伝わる順序にします。

| # | セクション | 目的 | 配置・レイアウト案 |
| --- | --- | --- | --- |
| 1 | **ヒーロー** | 一瞬で何屋か伝え、相談へ誘導 | 大型タイポ（2〜3行のコピー）を中央/左寄せ。背景は濃紺グラデ＋うっすらグリッドやグロー。CTA2つ（無料相談／サービスを見る）。下に実績数値（削減時間など） |
| 2 | **課題提起** | 共感をつくる | 「ツールを入れたが使われない」「IT人材がいない」等の"あるある"を3〜4枚のカードで |
| 3 | **私たちの強み（伴走）** | 差別化の核 | 「導入して終わりにしない」を図解。導入→定着→自走の3ステップ横並び |
| 4 | **サービス概要** | 3事業を提示 | 3カード（AI導入支援／受託開発／人材育成）。各カードから詳細へ |
| 5 | **導入事例（実績）** | 信頼の証明 | 主役は「月50時間削減」。Before→Afterと数値を大きく見せる。詳細リンク |
| 6 | **数字で見る成果** | 説得力 | 削減時間・対応社数・継続率などをカウントアップ表示 |
| 7 | **料金・プラン** | 不安解消 | 参考価格（初期費用・月額）を3プラン程度で。「要見積もり」も明記 |
| 8 | **ご利用の流れ** | 心理的ハードルを下げる | 相談→提案→伴走→自走の4ステップ |
| 9 | **FAQ** | 最後の不安をつぶす | アコーディオン3〜4問 |
| 10 | **最終CTA** | 行動 | 「まずは30分、無料で話しませんか？」を大きく |
| 11 | **お知らせ抜粋** | 活動の鮮度 | 最新記事3件をカード表示 |

## 4. 各ページの中身

### 4-1. サービス詳細（/services）
- 冒頭に3事業へのアンカーナビ
- **AI導入支援・DXコンサル**：ツール選定〜業務自動化までの工程、対応領域（バックオフィス自動化など）
- **受託システム開発**：得意領域、開発の進め方
- **IT人材育成・研修**：研修メニュー、内製化支援の内容
- 各事業の末尾に「この事業について相談する」CTA

### 4-2. 導入事例（/works）
- 代表事例：**中小企業バックオフィスのAI自動化で月50時間削減**
  - 課題 / 実施内容（ツール選定・自動化フロー）/ 成果（数値）/ お客様の声
- 数値はヒーロー級に大きく見せる

### 4-3. 料金・プラン（/pricing）
- 前提：「ご相談内容に応じた個別見積もり」を明記
- 参考価格テーブル（例。実数値は要確認）

| プラン | 想定 | 初期費用（参考） | 月額（参考） |
| --- | --- | --- | --- |
| スポット相談 | 単発の課題整理 | ¥0〜 | — |
| 導入支援 | ツール選定〜定着 | 要見積もり | ¥◯◯〜 |
| 伴走サポート | 継続的な内製化支援 | 要見積もり | ¥◯◯〜 |

> ※実際の金額・プラン名はヒアリングのうえ確定します。

### 4-4. 会社概要・メンバー（/about）
- ミッション/ビジョン、会社情報テーブル
- メンバー紹介カード（写真・名前・役割・一言）

### 4-5. お知らせ／ブログ（/news）
- 記事一覧（カード、カテゴリタグ、日付）＋記事詳細
- 初期は静的Markdown運用、将来CMS（microCMS等）連携も可能な設計に

### 4-6. お問い合わせ（/contact）
- フォーム：会社名 / 氏名 / メール / 電話 / 相談内容 / 希望日時
- **無料オンライン相談（30分）への導線**を主役に。カレンダー予約（Googleカレンダー/Calendly等）連携も想定

## 5. デザイン仕様

### カラーパレット（ダークモード）

| 用途 | 色 | 参考値 |
| --- | --- | --- |
| 背景（ベース） | ほぼ黒〜ディープネイビー | `#0A0E1A` / `#0D1226` |
| サーフェス（カード） | やや明るい濃紺 | `#141A33` |
| テキスト（主） | オフホワイト | `#E8ECF4` |
| テキスト（副） | グレイッシュ | `#8A93A8` |
| アクセント1（テックブルー） | 先進的な青 | `#3B82F6` / `#2DD4FF` |
| アクセント2（ネオングリーン） | CTA・強調 | `#22F5A0` / `#39FF88` |
| 罫線・区切り | 低コントラスト | `rgba(255,255,255,0.08)` |

- アクセントは**面ではなく点で**使う（ボタン、数値、リンク、グロー）。多用せず先進感を保つ。
- ヒーローやCTAにはブルー→グリーンの**グラデーション**やうっすらした**グロー（発光）**を効かせる。

### タイポグラフィ
- 欧文：`Inter` / `Manrope` など、視認性の高いモダンサンセリフ
- 和文：`Noto Sans JP`（ウェイトを絞ってミニマルに）
- ヒーロー見出しは特大（デスクトップで64〜88px相当）＋字間を詰めてインパクト
- 本文は行間広め（1.7〜1.8）で余白を活かす

### レイアウト・余白
- 最大幅 約1200px、左右にたっぷり余白
- セクション間の縦余白を大きく取り、要素を詰め込まない（Apple/上品なSaaS的）
- カードは角丸（12〜16px）＋微細なボーダー＋ホバーで浮く

### モーション
- **スクロールで"ふわっと浮き出る"**フェード＋スライドアップ（Intersection Observer）
- 数値のカウントアップ、ホバー時の軽いリフト/グロー
- `prefers-reduced-motion` に対応し、動きを抑えたい人には静的表示

## 6. 技術構成（実装フェーズの提案）

要望（ダーク基調・アニメ・複数ページ・将来のブログCMS）を踏まえ、2案を提示します。

| 項目 | 案A：静的HTML + Tailwind | 案B：Next.js + Tailwind（推奨） |
| --- | --- | --- |
| 向き | 早く公開・低コスト | 拡張性・ブログ運用・SEO |
| ページ追加 | 手作業 | コンポーネントで効率的 |
| ブログ | Markdown手動 | MDX / microCMS連携が容易 |
| ホスティング | GitHub Pages | Vercel など |
| 学習/保守 | 容易 | ややリッチ |

> 「お知らせ（ブログ枠）」を継続運用される想定なら **案B（Next.js）** を推奨します。まず案Aで素早く形にして後で移行する選択も可能です。

## 7. 実装の進め方（合意後）

1. 本提案へのフィードバック反映（配色・コピー・プラン・技術構成の確定）
2. デザイントークン（色/余白/フォント）と共通レイアウト（ヘッダー/フッター）を実装
3. トップページを最優先で実装 → セクション単位でレビュー
4. 下層ページ（サービス/会社概要/お知らせ/問い合わせ）を順次実装
5. アニメーション・レスポンシブ・アクセシビリティ調整
6. 公開設定（ホスティング/独自ドメイン）
